ChurchManager – Phase 1 : conception et structuration

Application Web de gestion d’église. Ce document couvre l’architecture, l’arborescence, la base de données, l’authentification, le design et la remontée des données vers Google Sheets. Aucun module n’est développé avant votre validation.

1. Architecture technique

Décision importante. Une page HTML avec JavaScript ne peut pas se connecter directement à MySQL : le navigateur exposerait les identifiants de la base. Il faut une couche serveur. Je retiens PHP 8 + PDO (hébergement courant et peu coûteux), sans framework lourd.
CoucheChoixRôle
FrontendHTML5, CSS3, JavaScript, Bootstrap 5, Chart.jsPages, formulaires, graphiques, calendrier. Appels fetch() vers l’API.
BackendPHP 8, architecture modulaire (contrôleur / service / dépôt)Logique métier, sécurité, permissions, exports.
Base de donnéesMySQL 8, InnoDB, utf8mb4Tables normalisées, clés étrangères, index.
ExportsDompdf (PDF), PhpSpreadsheet (Excel)Rapports imprimables.
SynchronisationGoogle Apps Script + file d’attente sync_queueCopie des données vers Google Sheets (section 6).

Principes

Une requête = un point d’entrée unique (public/index.php) qui charge le routeur, vérifie la session, le jeton CSRF et la permission requise, puis appelle le module. Chaque module est autonome (modules/membres, modules/finances…). Les textes sont stockés dans lang/fr.php pour ajouter ht.php et en.php plus tard.

Script SQL de création (Phase 1)

CREATE DATABASE churchmanager CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE churchmanager;

CREATE TABLE roles(
  id TINYINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  code VARCHAR(30) NOT NULL UNIQUE, libelle VARCHAR(60) NOT NULL
) ENGINE=InnoDB;
CREATE TABLE permissions(
  id SMALLINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  code VARCHAR(60) NOT NULL UNIQUE, libelle VARCHAR(120) NOT NULL
) ENGINE=InnoDB;
CREATE TABLE role_permissions(
  role_id TINYINT UNSIGNED NOT NULL, permission_id SMALLINT UNSIGNED NOT NULL,
  PRIMARY KEY(role_id,permission_id),
  FOREIGN KEY(role_id) REFERENCES roles(id) ON DELETE CASCADE,
  FOREIGN KEY(permission_id) REFERENCES permissions(id) ON DELETE CASCADE
) ENGINE=InnoDB;

CREATE TABLE membres(
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  matricule VARCHAR(20) NOT NULL UNIQUE,
  photo VARCHAR(255) NULL,
  nom VARCHAR(80) NOT NULL, prenom VARCHAR(80) NOT NULL,
  sexe ENUM('M','F') NOT NULL, date_naissance DATE NULL,
  telephone VARCHAR(30) NULL, email VARCHAR(120) NULL, adresse VARCHAR(255) NULL,
  date_integration DATE NULL, date_bapteme DATE NULL,
  statut ENUM('actif','inactif','transfere','decede','archive') NOT NULL DEFAULT 'actif',
  urgence_nom VARCHAR(120) NULL, urgence_telephone VARCHAR(30) NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX(nom,prenom), INDEX(statut), INDEX(telephone)
) ENGINE=InnoDB;

CREATE TABLE users(
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  role_id TINYINT UNSIGNED NOT NULL,
  membre_id INT UNSIGNED NULL,
  actif BOOLEAN NOT NULL DEFAULT TRUE,
  tentatives TINYINT UNSIGNED NOT NULL DEFAULT 0, verrouille_jusqua DATETIME NULL,
  derniere_connexion DATETIME NULL,
  FOREIGN KEY(role_id) REFERENCES roles(id),
  FOREIGN KEY(membre_id) REFERENCES membres(id) ON DELETE SET NULL
) ENGINE=InnoDB;

CREATE TABLE departements(
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  nom VARCHAR(100) NOT NULL UNIQUE, description TEXT NULL,
  responsable_id INT UNSIGNED NULL, date_creation DATE NULL,
  statut ENUM('actif','inactif') NOT NULL DEFAULT 'actif',
  FOREIGN KEY(responsable_id) REFERENCES membres(id) ON DELETE SET NULL
) ENGINE=InnoDB;
CREATE TABLE membre_departement(
  membre_id INT UNSIGNED NOT NULL, departement_id INT UNSIGNED NOT NULL,
  fonction VARCHAR(80) NULL, date_adhesion DATE NULL,
  PRIMARY KEY(membre_id,departement_id),
  FOREIGN KEY(membre_id) REFERENCES membres(id) ON DELETE CASCADE,
  FOREIGN KEY(departement_id) REFERENCES departements(id) ON DELETE CASCADE
) ENGINE=InnoDB;

CREATE TABLE visiteurs(
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  nom VARCHAR(80) NOT NULL, prenom VARCHAR(80) NOT NULL,
  telephone VARCHAR(30) NULL, adresse VARCHAR(255) NULL,
  date_visite DATE NOT NULL, nombre_visites SMALLINT UNSIGNED NOT NULL DEFAULT 1,
  observations TEXT NULL, suivi_par INT UNSIGNED NULL,
  souhaite_devenir_membre BOOLEAN NOT NULL DEFAULT FALSE,
  converti_membre_id INT UNSIGNED NULL,
  FOREIGN KEY(suivi_par) REFERENCES users(id) ON DELETE SET NULL,
  FOREIGN KEY(converti_membre_id) REFERENCES membres(id) ON DELETE SET NULL,
  INDEX(date_visite), INDEX(nom,prenom)
) ENGINE=InnoDB;

CREATE TABLE categories_finance(
  id SMALLINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  nom VARCHAR(80) NOT NULL, type ENUM('revenu','depense') NOT NULL,
  UNIQUE(nom,type)
) ENGINE=InnoDB;
CREATE TABLE clotures(
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  periode ENUM('jour','mois','annee') NOT NULL,
  date_debut DATE NOT NULL, date_fin DATE NOT NULL,
  total_revenus DECIMAL(14,2) NOT NULL, total_depenses DECIMAL(14,2) NOT NULL,
  cloture_par INT UNSIGNED NOT NULL, cloture_le DATETIME NOT NULL,
  UNIQUE(periode,date_debut),
  FOREIGN KEY(cloture_par) REFERENCES users(id)
) ENGINE=InnoDB;
CREATE TABLE operations(
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  reference VARCHAR(25) NOT NULL UNIQUE,
  date_operation DATE NOT NULL, categorie_id SMALLINT UNSIGNED NOT NULL,
  description VARCHAR(255) NULL,
  montant DECIMAL(14,2) NOT NULL CHECK (montant > 0),
  mode_paiement ENUM('especes','cheque','virement','mobile') NOT NULL,
  saisi_par INT UNSIGNED NOT NULL, cloture_id INT UNSIGNED NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY(categorie_id) REFERENCES categories_finance(id),
  FOREIGN KEY(saisi_par) REFERENCES users(id),
  FOREIGN KEY(cloture_id) REFERENCES clotures(id),
  INDEX(date_operation), INDEX(categorie_id)
) ENGINE=InnoDB;

CREATE TABLE evenements(
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  titre VARCHAR(150) NOT NULL,
  type ENUM('culte','priere','conference','seminaire','retraite','bapteme','mariage','autre') NOT NULL,
  description TEXT NULL, date_evenement DATE NOT NULL, heure TIME NULL,
  lieu VARCHAR(150) NULL, responsable_id INT UNSIGNED NULL,
  statut ENUM('planifie','en_cours','termine','annule') NOT NULL DEFAULT 'planifie',
  FOREIGN KEY(responsable_id) REFERENCES membres(id) ON DELETE SET NULL,
  INDEX(date_evenement)
) ENGINE=InnoDB;
CREATE TABLE presences(
  id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  evenement_id INT UNSIGNED NOT NULL,
  membre_id INT UNSIGNED NULL, visiteur_id INT UNSIGNED NULL,
  present BOOLEAN NOT NULL DEFAULT TRUE,
  FOREIGN KEY(evenement_id) REFERENCES evenements(id) ON DELETE CASCADE,
  FOREIGN KEY(membre_id) REFERENCES membres(id) ON DELETE CASCADE,
  FOREIGN KEY(visiteur_id) REFERENCES visiteurs(id) ON DELETE CASCADE,
  UNIQUE(evenement_id,membre_id), UNIQUE(evenement_id,visiteur_id),
  CHECK ((membre_id IS NULL) <> (visiteur_id IS NULL))
) ENGINE=InnoDB;

CREATE TABLE journal_audit(
  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  user_id INT UNSIGNED NULL, action VARCHAR(40) NOT NULL,
  table_name VARCHAR(40) NULL, record_id INT UNSIGNED NULL,
  details JSON NULL, ip VARCHAR(45) NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE SET NULL,
  INDEX(created_at), INDEX(table_name,record_id)
) ENGINE=InnoDB;
CREATE TABLE sync_queue(
  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  table_name VARCHAR(40) NOT NULL, record_id INT UNSIGNED NOT NULL,
  action ENUM('upsert','delete') NOT NULL DEFAULT 'upsert',
  statut ENUM('attente','envoye','erreur') NOT NULL DEFAULT 'attente',
  tentatives TINYINT UNSIGNED NOT NULL DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, INDEX(statut)
) ENGINE=InnoDB;

Une opération appartenant à une clôture est verrouillée : le backend refuse sa modification.

6. Remontée des données vers Google Sheets

Principe : à chaque création, modification ou suppression, le backend ajoute une ligne dans sync_queue. Une tâche planifiée (cron) envoie ces lignes à un script Google Apps Script, qui les écrit dans le classeur : un onglet par table. MySQL reste la source de vérité ; Google Sheets sert de copie de consultation.

Étape 1 : préparer le classeur

  1. Créez un Google Sheets nommé « ChurchManager – Données ».
  2. Menu Extensions → Apps Script.
  3. Supprimez le code existant et collez le script ci-dessous (fichier sheets/apps_script.gs).
  4. Remplacez CHANGER_CE_SECRET par une longue chaîne aléatoire (32 caractères ou plus).
const SECRET = 'CHANGER_CE_SECRET';

function doPost(e) {
  const d = JSON.parse(e.postData.contents);
  if (d.token !== SECRET) return out({ok:false, error:'refuse'});
  const ss = SpreadsheetApp.getActive();
  const sh = ss.getSheetByName(d.table) || ss.insertSheet(d.table);
  if (sh.getLastRow() === 0 && d.row) sh.appendRow(Object.keys(d.row));
  const n = sh.getLastRow() - 1;
  const ids = n > 0 ? sh.getRange(2, 1, n, 1).getValues().flat().map(String) : [];
  const i = ids.indexOf(String(d.id));
  if (d.action === 'delete') {
    if (i >= 0) sh.deleteRow(i + 2);
  } else {
    const vals = Object.values(d.row);
    if (i >= 0) sh.getRange(i + 2, 1, 1, vals.length).setValues([vals]);
    else sh.appendRow(vals);
  }
  return out({ok:true});
}
function out(o) {
  return ContentService.createTextOutput(JSON.stringify(o))
    .setMimeType(ContentService.MimeType.JSON);
}

Étape 2 : publier le script

  1. Déployer → Nouveau déploiement → Application Web.
  2. Exécuter en tant que : Moi. Qui a accès : Tout le monde (l’accès est protégé par le secret).
  3. Autorisez les permissions demandées, puis copiez l’URL terminant par /exec.

Étape 3 : configurer l’application

  1. Dans app/config/config.php, renseignez SHEETS_URL (URL copiée) et SHEETS_SECRET (même secret). Ces valeurs ne doivent jamais apparaître dans le JavaScript du navigateur.
  2. La classe core/SheetsSync.php lit les lignes statut='attente', charge l’enregistrement, puis envoie en cURL : {"token":…,"table":"membres","id":12,"action":"upsert","row":{…}}. En cas de succès, la ligne passe à envoye ; sinon erreur avec nouvelle tentative (3 maximum).
  3. Planifiez la tâche toutes les 5 minutes : */5 * * * * php /chemin/churchmanager/cron/sync_sheets.php (cron de l’hébergeur).

Étape 4 : vérifier

  1. Ajoutez un membre test dans l’application.
  2. Lancez sync_sheets.php à la main, puis ouvrez le classeur : l’onglet membres doit contenir l’en-tête et la ligne.
  3. Modifiez le membre : la même ligne est mise à jour, sans doublon.
Confidentialité. Les fiches de membres sont des données personnelles. Gardez le classeur privé, partagez-le uniquement avec les personnes autorisées, et n’envoyez pas les colonnes sensibles inutiles (photo, contact d’urgence). Les opérations financières restent visibles seulement du trésorier et du pasteur.

7. Validation demandée

Points à confirmer avant la Phase 2 :

  1. Accord sur l’ajout de PHP 8 comme couche serveur (obligatoire pour MySQL).
  2. Devise utilisée (gourde haïtienne, dollar américain ou les deux).
  3. Hébergement prévu (local avec XAMPP ou serveur en ligne), car cela fixe la méthode de planification du cron.
  4. Colonnes à envoyer vers Google Sheets (toutes les tables ou seulement membres, visiteurs et finances).

Dès votre validation, je développe la Phase 2 en commençant par le socle commun (configuration, connexion, mise en page) puis le tableau de bord.
